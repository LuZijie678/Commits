# Git LFS 与运行时输出策略

## 适用范围

本仓库主要保存代码、配置、文档、测试，以及少量被明确纳入版本管理的规范化数据资产。

时间戳命名的实验输出属于运行时产物，不应提交到仓库。

## 允许进入 Git 的内容

- 源代码、配置、测试和文档
- 明确作为输入资产管理的 `datasets/**`
- 明确作为长期归档管理的 `archive/**`

## 必须忽略的内容

- 运行时实验目录，如 `outputs/llm_generation_*`、`outputs/step3_*`
- prompt dump、generation 输出、预测结果、请求缓存、judge 缓存
- 临时评测结果、临时 JSONL、临时调试导出

## Git LFS 的使用原则

- 只有当大文件是“刻意版本化的规范输入”时，才适合使用 Git LFS。
- 运行时 `outputs/**` 不应放入 LFS。
- 运行时结果应保留在本地；若确有必要，只应提炼小型总结再升格到 `reports/` 或 `docs/`。

## 为什么 `.gitignore` 不够

- `.gitignore` 只能阻止新文件被追踪。
- 已经进入 Git 的运行时目录，还需要 `git rm --cached` 或等价方式解除追踪。

## 历史清理

- 如果发现历史运行时目录进入 Git，应优先移出索引，而不是把它们继续当作文档或输入资产。
